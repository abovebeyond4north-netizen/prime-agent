# Composition transfer: failed acceptance

2026-10-26. The unchanged learner was tested on 48 disjoint affine functions:
multipliers -32, -16 and 64, each with offsets -8..7. Three arms receive 10,000
primitive evaluations per task: primitive-only, learned composition and a
matched-length identity composition (`negate, negate`). Arm order rotates.
Training plus compression time is charged to learned reuse. An independent
symbolic affine interpreter checks every returned program's coefficients.

Each of three recorded repetitions gives:

| Arm | Solved | Primitive evaluations (search only) |
| --- | ---: | ---: |
| Primitive-only | 44/48 | 185,517 |
| Learned | 40/48 | 268,992 |
| Irrelevant identity | 38/48 | 268,875 |

Reuse loses baseline successes at (64,-8), (64,-4), (64,-2), (64,-1).
Recorded search plus applicable setup times in milliseconds:
primitive 66.69 / 56.96 / 54.31; learned 84.41 / 65.43 / 66.43;
identity 68.96 / 62.14 / 61.93. Timings are short and noisy, not portable estimates.
The learner is neither promoted nor changed in response to these evaluation results.

Acceptance required no lost baseline tasks and lower end-to-end time than both
controls in every repetition. It failed both coverage and timing requirements.
This limits the previous favorable development result: a useful repeated
composition is not necessarily a good universal search priority.

Two new unit tests pass. Detailed task-level costs/timings and learner SHA-256
are in `composition_validation_results.json`; program bodies are omitted from
that compact receipt but can be regenerated by `python -m research.composition_validation`.
The first execution's console output was truncated; the recorded execution was
repeated without modifying learner, tasks, budget, or acceptance criteria.

This is same-operator internal evaluation, not externally protected validation.
Three repetitions are timing repetitions, not independent replications. No paid
calls, generated Python execution, promotion, or production change occurred.
Future search-policy changes must use a new validation set: this set is now seen.
Next investigate budget-safe optional reuse rather than unconditional macro priority;
do not claim no-regression guarantees from splitting a fixed baseline budget.
